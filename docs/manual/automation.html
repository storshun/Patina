Claude and automation

Every action in Patina is also a command. Claude can call the commands through MCP, scripts can call them over a local socket, other applications over HTTP (see HTTP API and batch mode), and you can type them in the Console. Claude can set up layer stacks, paint, unwrap, export, and look at the result.

Connecting Claude (MCP)

The Claude desktop app

Open the Blender Link panel and click Connect to Claude app, or run patina --setup-claude. Then quit the Claude app completely and open it again. Patina adds itself to the app's MCP servers in claude_desktop_config.json (~/.config/Claude/ on Linux, %APPDATA%\Claude\ on Windows), with the full path to this copy of Patina. Other servers, such as Blender MCP, and other settings are kept. The previous file is saved next to it as claude_desktop_config.json.bak. On Windows the entry points to patina-cli.exe, because the app talks to Patina over stdin/stdout. Once it is set up, the panel shows The Claude app can drive this window.

"Patina isn't connected to this chat"The Claude app reads its MCP servers only when it starts, so restart it after connecting. Keep a Patina window open if you want Claude to work in it. Otherwise Claude starts its own Patina without a window. If the button reports that the file is not valid JSON, fix or remove the file first: Patina never overwrites a configuration it can't read.

Claude Code and other MCP clients

claude mcp add patina -- ~/.local/bin/patina --mcp                     # Linux
claude mcp add patina -- "%LOCALAPPDATA%\Programs\Patina\patina-cli.exe" --mcp   # Windows

Any other MCP client works with the same command. For example, in a JSON configuration:

{ "mcpServers": { "patina": { "command": "/home/you/.local/bin/patina", "args": ["--mcp"] } } }

patina --mcp chooses one of two modes when it starts:

ModeWhenWhat Claude sees
LiveA Patina window is already openClaude works in your window. You see every stroke, and screenshot_window returns exactly what is on your screen.
HeadlessNo window is openPatina runs off-screen. render_view and render_uv return pictures. open_gui_window hands the project to a real window at any time, and later calls then drive that window.

What Claude gets to work with (0.34)

Every tool comes with its settings: their type, their range, their default, and a sentence on what moving them does (“Lower: more, closer pieces”). On top of the tools, the MCP server gives agents:

WhatFor
Guides (the patina_guide tool, and the resources patina://guide/…) workflow: the order of the tools from opening a model to exporting it; mesh: checking, mending, transforming, reducing and collision, setting by setting; develop: the adjustment layer's settings and how to tune them by numbers; export: formats, sizes, levels of detail and collision names per engine; batch: recipes and batches; painting; and parameters: every setting of every tool, written from the tools themselves so it is always up to date.
PromptsFinish a model (for a game, the web, printing or rendering), Develop the textures, Make it game ready (Unreal, Godot or Unity) and Batch a folder. In Claude Code they are slash commands such as /mcp__patina__finish_model.
Numbers to check bymesh_check (problems), mesh_reduce with preview (how far the shape would move), mesh_collision (fit), and texture_check: how much of the color is out of a real material's range, the color cast and spread, with hints naming the setting to move. Claude changes a setting, measures, and looks with render_view.

Things to ask Claude

  • “Finish ~/Downloads/robot.glb for Godot: mend it, keep it under 20,000 triangles, convex collision, two levels of detail.”
  • “The textures of this scan are too dark and orange, and the creases are baked in. Develop it to a neutral daylight look and tell me the settings.”
  • “Run the Game asset recipe on every model in ~/assets/props and tell me which failed.”
  • “Open ~/models/crate.glb, give it worn painted metal with rust on the edges and dirt in the cavities, and show me.”
  • “The UVs of this mesh overlap. Unwrap it with smart project, pack it, and check that the paint stayed in place.”
  • “Apply the rusted iron smart material, put a snow cover on top, and solo the snow folder so I can see it.”
  • “Paint a 2 cm red stripe around the middle of the barrel, then export for Unreal at 4K into ~/exports.”
  • “Compare three rust variations using an adjustment layer and take a screenshot of each.”

Claude can read the full list of tools with their parameters. Images (renders, screenshots, textures) are returned to it as pictures.

The console

The Console tab takes command {json}, for example:

add_layer {"type": "fill", "material": {"id": "patina_rust_heavy"}, "generator": {"type": "edges", "level": 0.55}}
paint_stroke {"points": [[0.4, 0.5], [0.6, 0.5]], "brush": {"size": 40}}
export_textures {"directory": "/tmp/out", "preset": "gltf"}

The command server

Patina listens on 127.0.0.1:7860 (change it with --port or PATINA_PORT). The protocol is newline-delimited JSON: one request per line, and one response per line with the same id.

import json, socket
s = socket.create_connection(("127.0.0.1", 7860)); f = s.makefile("rwb")
def call(cmd, **args):
    f.write((json.dumps({"id": 1, "cmd": cmd, "args": args}) + "\n").encode()); f.flush()
    return json.loads(f.readline())
print(call("get_state")["result"]["mesh"])
call("set_paint_material", id="patina_gold_polished")
call("paint_stroke", points=[[0.3, 0.5], [0.7, 0.5]])

To repeat a sequence of commands, record it with the macro recorder: every command a script or Claude runs while it records becomes a step, and the saved macro is a job file for patina run.

To run the same steps on many models, save them as a recipe and use a batch.

patina --headless runs only the server, with no window. scripts/patina_client.py in the source is a small ready-made client. For other applications, other machines, background jobs and job files, use the HTTP API and batch mode.

Coordinates

  • paint_stroke points are normalized viewport coordinates by default: 0–1, with the origin at the top left. "space": "uv" gives texture coordinates (origin at the bottom left) and "space": "viewport" gives pixels.
  • paint_world_points paints at 3D positions on the model, so you can work without the camera.
  • pick tells you what is under a viewport point: the 3D position, the UV and the current values.

The command reference lists every command with its parameters. The desktop window adds a few of its own: screenshot_window, pen_info (what the pen tablet sends) and set_pen_settings (the pressure curve and the pen buttons).

Gotchas

Windows: use patina-cli.exeMCP clients talk to the server over standard input and output, which only console programs have. Point the client at patina-cli.exe, not at patina.exe.
Two windows, one portA second Patina window can't open port 7860 while the first one has it. It still works, but Claude and Blender talk to the first window. Start the second window with --port 7861 if you need both.
Headless needs a GPU driver tooHeadless mode renders off-screen with the same OpenGL 4.5 code. Linux uses EGL, so no display server is needed. Windows uses a hidden window, so it needs a normal desktop session with a GPU driver.
SecurityThe server accepts connections only from this computer (127.0.0.1). Any program you run locally can drive Patina, but nothing on the network can. Start Patina with --no-server to turn the server off. The HTTP API can answer the local network, with a token; it is off unless you start it.
