Gotchas and troubleshooting

Things that surprise people, why they happen, and what to do about them. The other pages have their own gotchas too; this page gathers the important ones in one place.

Painting

Paint shows up in two places

Two parts of the model use the same area of the texture. That happens with mirrored halves, with stacked or duplicated islands, and with “UV tiles” that were collapsed into one. Each texel can hold only one color, so painting one part also paints the other. Patina warns about it when it loads the model.

Fix: give the overlapping parts their own space with UV › Unwrap › Smart UV Project, then Pack Islands. Existing paint is carried over. In Patina Web, use Unique UVs. If the mirroring is intentional, for example to save texture space, paint symmetrical details only, or paint on a mirrored copy in Blender.

A stroke stops at a hidden edge or goes through the model

Painting respects visibility: only surfaces you can see under the brush get paint. Turn on Paint through (Occlusion off) to reach hidden surfaces, and remember to turn it back off. Very thin geometry (cloth, leaves) may need paint-through on purpose.

Strokes are soft or blocky up close

That part of the model has too few texels. Raise the resolution, or scale its islands up in the UV editor. The UV checker view shows texel density.

Faint lines along UV seams

Seams are where the texture is cut, and filtering can pick up a little color from the other side. Keep Dilate seams on (Texture Set), and use resolutions of 2048 and up for final textures. Normal-map seams are smallest when islands follow the model's natural edges.

Materials and layers

The material looks stretched or blurred on one side

Tri-planar projection blends three directions. Where a surface faces diagonally, the directions meet. Raise Tri-planar blend, rotate the material, or switch to UV projection on a well-unwrapped model.

A pattern shows a faint second copy of itself (ghosting)

Two causes, both fixed in 0.7.4. Where tri-planar projections met, they were cross-faded, so two patterns showed at half strength (see tri-planar seams). On a symmetric island, both halves wrote their own values into the texels they share, leaving a patchwork of triangles with the left and right half's pattern; now the half that is unwrapped decides and the stacked half shows the same texels mirrored. Projects from older versions pick both fixes up when opened: fill layers and smart masks are recomputed. Paint strokes keep what they were painted with, so repaint strokes from an older version that still look doubled.

A smart mask puts wear in odd places

The AO / curvature bake is stale (re-bake after mesh or UV changes), or the mesh has no bevels, so all edges are equally sharp. Lower Level, add Noise, or paint the mask by hand.

A layer or the whole stack seems to have vanished

A layer is soloed: look for the yellow Solo: … button above the layer list and click it. Solo is not saved in the project, and exports ignore it.

Painting on a folder hid everything in it

The brush paints a folder's mask, and a new mask starts black, so only the painted spot shows. Undo, then use Add white mask on the folder and erase where it should be hidden.

Undo went further back than expected

Each slider change is its own step, recorded when you let go. A long session of tweaks becomes many small steps. The History panel shows them all. Click the step you want instead of pressing Ctrl+Z many times. Only the last 100 steps (or 1 GB of undo data) are kept.

A smart material with paint looks scrambled

Painted textures in a smart material follow the UV layout of the mesh they were painted on. Save smart materials without paint to use them on other models.

UVs

After unwrapping, the model shows no paint

UV › Keep paint on UV edits was off, so the paint stayed where it was in the texture while the UVs moved. Undo (Ctrl+Z), turn the option on, and unwrap again.

The Island brush made several small islands, or the whole layout moved

Each connected piece of the painted area becomes its own island; paint across gaps, or grow the selection (Ctrl+Numpad +). If the new island didn't fit into free space, all islands were repacked at an equal density, and the status bar says so. Paint moves with them, so the model looks the same. Undo, and pick a lower density in UV › Islands › Texel Density if you want the old layout kept.

The texel density heat map is mostly blue or red

The heat map compares every face with the target (UV › Islands › Texel Density). A model whose UVs come from a projection (like the Suzanne sample) varies a lot from face to face. Islands made with the Island brush, or Pack, even it out.

UV tiles / UDIMs

A model whose islands each sit inside one unit tile, across several tiles, opens with UDIM tiles: one texture per tile (see Texture sets and UDIM tiles). Check Texture Set › Texture sets if a model opens differently from what you expect.

Paint shows up on two parts of the model at once

Those parts share UV space. Mirrored halves stacked on purpose do that. If they are different material slots (body and clothes each laid out over the whole texture), choose Texture Set › Texture sets › Per material slot. Otherwise use UV › Fix Overlapping UVs.

Exporting

Wrong colors or shading in another program

Only base color and emission are sRGB color images. All other maps are data: import them as Non-Color / linear. If the normal map makes bumps look like dents, the program expects the other green-channel convention. Use the Unreal preset (DirectX) or flip green.

The export file names are not what I typed

Unknown $tokens stay as typed, and characters that are not allowed in file names (/ \ : * ? " < > |) are replaced with _. The example under the template shows the real name before you export.

The baked high-poly detail has flat patches

Some texels didn't find the sculpt within the cage Distance. Make sure both meshes were exported from the same Blender scene with the same transform, then raise Distance in Bake › From a High-poly Mesh. The status bar reports how many texels found the sculpt.

Export Again is grayed out

Nothing has been exported from this project yet. Export once with Ctrl+E; after that Ctrl+Shift+E repeats it, also after reopening the project. Exports to Blender through the bridge don't count.

Textures exported but Blender didn't update

The bridge isn't linked (see the status bar), or Blender's listener is off. In Blender, check that Live Link is running, then press Ctrl+B in Patina or Pull Textures in Blender.

Pen tablets

No pressure from the tablet

Open Help › Pen Tablet Test. If it says No pen events yet while you move the pen, the driver hands the pen to applications as a mouse: on Windows enable Windows Ink in the Wacom / Huion settings; on Linux check sudo libinput debug-tablet. Details in Pen tablets.

The pen's buttons do the wrong thing

Set them in Preferences › Pen tablet (right click, middle click, swap colors, undo, nothing). If they still send keys or something else, the tablet driver has remapped them; set them to the default (right / middle click) there.

Substance files and the API

A .sbsar (or .spsm, .spp) won't open

Those are Adobe's own formats: an .sbsar needs Adobe's Substance engine to render. Export the material's outputs as images from Substance Designer, Sampler or Player, then import that folder (see Materials from Substance). Exported texture folders, including packed ORM / MaskMap maps and EXR files, import directly.

Another machine can't reach the HTTP API

Check, in order: Patina was started with --lan (or Local network is ticked in Preferences); the firewall lets port 7870 in from your network; the client's address is private (10.x, 172.16–31.x, 192.168.x), otherwise add its range with --allow; the client sends the token. The Patina log names every refused address. See who can connect.

The API answers 409 "busy"

A job is using the engine. Queue your work as a job too (POST /api/v1/jobs), or wait longer with ?busy_wait=120.

Keys and settings

A key stopped doing what it used to

In 0.3, X swaps the paint colors and the X mirror is on Shift+X. Tab hides all panels (press it again). Any shortcut can be changed back in Edit › Keyboard shortcuts. Two actions on the same key are shown in red there, and only the first one fires.

U makes an island instead of selecting Blur

Since 0.4, U in the Blender keymap does what Blender's Unwrap does: it makes an island from the painted faces. Blur has no key there; give it one in Edit › Keyboard shortcuts. In the Patina keymap U is still Blur.

Patina asks to recover work, or says the mesh changed

“Recover your work?” appears when Patina didn't close properly last time and an autosave exists. “Mesh changed on disk” appears when another program saved the .glb / .obj you opened. Updating keeps your layers. Both are described in Projects.

S, F or Tab do something unexpected

The Blender keymap is on: S samples a color, F resizes the brush and Ctrl+Space hides the panels. Edit › Preferences shows which keymap is active and switches back to the Patina one. See the Blender keymap reference.

Patina starts with odd brush settings or a tiny UI

Brush, colors, UI scale and other choices are restored from session.json in the settings folder (Help › About shows where). Use View › UI scale › 100%, or quit and delete that file to get the defaults back. keymap.json next to it holds the shortcuts.

System and setup

“Could not create an OpenGL 4.5 context”

The graphics driver is missing or too old, or you are in a VM or remote session that provides only basic OpenGL. Update the GPU driver. On Fedora, sudo dnf install mesa-dri-drivers; for NVIDIA, use the RPM Fusion driver. On Windows, install the driver from your GPU vendor, not the generic Microsoft one.

Wayland and pen pressure

The prebuilt Linux binary runs through XWayland. Tablets work through XInput2, but some desktops report pressure only to native Wayland apps. Build from source with SDL3-devel installed for native Wayland.

File dialogs don't open (Linux)

Patina uses zenity (or kdialog) for file dialogs. Install one with sudo dnf install zenity. Dragging and dropping files always works.

Windows: “Windows protected your PC”

The download isn't code-signed. Choose More info › Run anyway. Install it from a folder you own. Don't use Program Files, so Patina can update its files without administrator rights.

File names with accents or non-Latin characters

These are supported on Linux. On Windows they need Windows 10 1903 or later, because Patina relies on the system's UTF-8 support.

Port 7860 is already in use

Another Patina window (or another program) has the port. The second window still works, but automation talks to the first one. Start it with --port 7870, and set the same port in the Blender add-on and the MCP command if you want those to use it.

The app is slow at 4K / 8K

Every stroke updates the whole texture set on the GPU. At 4K and above, with many layers, an integrated GPU will struggle. Paint at 2K, then switch the resolution up before exporting. Layers are resampled.

Windows build status

Windows build statusThe Windows version is cross-compiled from Linux. It is built from the same code as the Linux app, which passes its automated tests, but the Windows binaries themselves haven't been run on Windows yet. If something behaves differently on Windows, run patina-cli.exe from a terminal: it prints the log, including the OpenGL driver it found.
